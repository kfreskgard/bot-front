# bot-front Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small internet-facing service that logs Kim in with one password and shows the bot's positions per day, read from bot-back's `GET /view/positions`, over HTTPS it manages itself.

**Architecture:** Hono app with server-rendered JSX pages and htmx polling, built by `createApp(deps)` so every route is testable in-process. Auth, the bot-back client, summary maths and TLS are separate modules that don't know how pages render. `server.ts` wires them to a port-80 server (ACME challenges and an https redirect) and a port-443 server with a hot-swappable certificate.

**Tech Stack:** TypeScript (ESM) run with `tsx`, `hono` 4.x, `@hono/node-server` 2.x, `acme-client` 5.x, htmx 2.0.x (vendored), Node's built-in test runner.

**Spec:** `docs/superpowers/specs/2026-10-22-bot-front-design.md` (after Task 1, the bot-front copy): Environment constraints, Architecture, Interface contract, Part 2, and the bot-front rows of Error handling, Testing and Rollout. Execute this plan only after the bot-back plan (`2026-10-22-bot-back-view-api.md`) is deployed.

## Global Constraints

- Repository: `C:\Users\Kim\Documents\GitHub\bot-front` already exists (created by Kim): empty, branch `main`, `origin` = `https://github.com/kfreskgard/bot-front.git`. Never push; Kim pushes.
- Runtime dependencies are exactly `hono`, `@hono/node-server`, `acme-client`. No native modules. Passwords use `crypto.scrypt`.
- Runs with `tsx` (`"start": "tsx src/server.ts"`), Docker base `node:22-alpine`, classic Dockerfile syntax (Docker 19.03, no BuildKit).
- `package.json` has `"type": "module"`. `tsconfig.json`: `target ES2022`, `module ESNext`, `moduleResolution Bundler`, `jsx react-jsx`, `jsxImportSource hono/jsx`, `strict`, `noEmit`, `include ["src","test","scripts"]`.
- Tests in `test/`, run by `"test": "tsx --test \"test/**/*.test.ts\""`.
- No inline scripts or styles anywhere (CSP `default-src 'self'`). htmx indicator styles are disabled with `<meta name="htmx-config" content='{"includeIndicatorStyles":false}'>`.
- Display formatting is Swedish via `Intl` `sv-SE`: group separator U+00A0, minus sign U+2212. Times are shown in Europe/Stockholm.
- bot-front never recomputes position status or results. It only sums them for the summary.
- User-visible strings are exactly as the spec writes them: summary lines, "Bot unreachable since HH:MM", "Bot error: <message>", "Invalid date", "Updated HH:MM:SS", "unpriced", "untracked".

## Review Focus

- A password with å/ä/ö: `hash-password` and login must hash identical UTF-8 bytes, or Kim is locked out of their own site. Test: Task 2.
- bot-back answering 200 with something that isn't the JSON contract (HTML from a wrong `botBackUrl`, truncated body): show the "Bot error" panel, never a 500 or a crash. Test: Task 5.
- An empty or missing `password` field on `POST /login` is a normal failed attempt ("Wrong password", counted by the limiter), not an exception. Test: Task 8.
- A stock name containing `&` or `<` (e.g. "H&M") must render escaped, not break the table. Test: Task 9.
- The port-80 redirect builds its target from the configured `domain`, never from the request's `Host` header (no open redirect). Test: Task 10.
